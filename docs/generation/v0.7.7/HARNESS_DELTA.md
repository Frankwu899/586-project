# Harness integration delta

Read the preserved [v0.7.6 integration brief](../v0.7.6/HARNESS_INTEGRATION.md)
first. Its implementation gaps remain; this instruction-only revision fixes none
of them in runtime code.

## Loading and presentation
Load SKILL.md, the shared method, editorial standard, quality policy and one
requested module guide. Load the research guide when a material context question
arises. Do not send all module guides, calibration examples or evaluator answer
keys on every request. Record the complete dependency digest in provenance/cache
keys so revised instructions cannot reuse an older artifact as a fresh result.

Map the concise result, supporting evidence and material warnings into supported
contracts and UI states. These are conceptual presentation layers, not approved
JSON field names. In a text-only caller, supporting notes can follow the main
artifact; do not claim expandable UI exists. Preserve Belinda's accepted Glassmorphism
baseline when future UI work implements this behavior.

Structure retains its graph. A short diagnosis makes goal/message/audience/attention
and logic accessible without a mandatory card for every question. Keep alternative
hypotheses and their uncertainty. For Storyboard, keep separate dialogue, screen
text, sound and timing fields under the four-column presentation.

## Research and interaction
Make source lookup conditional on a material gap. The host must supply tools,
relevant limits, source metadata and meaningful in-progress/failure states.
Proactive research is not authorization for a new paid call or always-on extra
research stage. Preserve the initial Structure draft, bounded operation accounting
and accepted edits. No research restart during semantic repair.

Separate external source statements, approved task facts and model inference.
Newly discovered claims about the user's product require adoption before they
become approved facts. No cited webpage can replace missing visual evidence.

Use one focused material question by default; up to three independent questions
is a presentation guideline, not a new generation prerequisite. Use interactive
controls where supported. Otherwise return an explicit needs-decision result and
useful unaffected content. Persist an answer only through normal host workflows.

## Still required before runtime parity
- Flexible Idea cardinality and removal of the fixed faithful/reorganized A/B prompt.
- Explicit skill loading/versioning; current providers use embedded guidance.
- Safe discussion-draft representation and exports with warnings.
- Experimental status, hypothesis and validation continuity.
- Deterministic checks, accountable repair/retry handling and approval/revision integrity.

Natalie's merged QA documents provide review criteria and recorded cases, not an
executed comprehensive deterministic suite. Separate evidence extraction defects
from downstream reasoning failures: the Dior visual/OCR failures require upstream
investigation as well as truthful coverage handling. Generation rules cannot recover
unseen text by assertion.

## Evaluation sequence
Use fictional development exercises for instruction checks, then agreed real
development material for harness calibration. Preserve unseen material for evaluation.
Freeze input revisions, upstream evidence, prompt/skill digest and cache mode when
Andrea compares models. Fix the model when comparing skill revisions. Human
review should assess concise usefulness alongside grounding, differentiation,
fidelity and feasibility. Neither mock tests nor these authoring exercises prove
live quality, latency, cost or advertising effectiveness.
