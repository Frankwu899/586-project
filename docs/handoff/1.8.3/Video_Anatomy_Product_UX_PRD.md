# Video Anatomy｜产品与交互重整 PRD
**版本 1.8.3 · 实施规格 · 2026-11-17 · COMM586**  
**基线：**1.8.2 Mac 测试包，PR #19，`bd93bfc884b70be81bbf93ddf2c72b42cea7dafc`。11 月 17 日核对远端，该 PR 仍为 Open Draft，基于 1.8.1 分支。本文定义下一版 1.8.3；以已确认决定和 UI 预览为输入。1.8.3 尚未实施或发布。

## 1. 产品定位与边界

Video Anatomy 是给品牌团队、代理商和视频创意专业人员用的制作前工作台。用户带着一个商业任务、一组参考视频或一个初步方向进来；离开时有一张可以交给制作团队的 Storyboard Sheet 与简短拍摄 Brief，且能说明创意借鉴了什么、证据在哪里、哪些主张允许使用。

产品承诺：**把参考视频中值得借鉴的手法，转成自己的拍摄方案。** 像 Premiere / DaVinci 一样组织素材、播放和定位证据。做到可交付的 Storyboard Sheet 与简短拍摄 Brief 为止。剪辑、混音、渲染、生成视频、自动发布、日历排期及共享托管不进入本轮。Discover 仍是 1.8 范围内的预留入口，由 Frank 定义；本轮不设计抓取、排名、下载或授权策略。

### 用户进入时可能已经知道什么

| 起点 | 最短可用路径 |
| --- | --- |
| 有 Brief、还没有方向 | Overview 导入资料并确认上下文 → 可选看参考 → Content plan 比较两个方向 → 批准并进 Production |
| 只有一条或多条参考视频 | Resources 上传/选择 → Source Review 核对证据 → Analysis 理解手法 → Content plan 探索。Brief 尚不完整时也能推进；正式制作前再补所需信息 |
| 已有方向、不需要参考 | Overview 补项目必要信息 → Plan a video → 写自己的方向 → 批准 → Production。不强制上传或付费分析 |
| 要做一组视频 | 按需建 Series，再建具体 Video。每条视频各自选方向、批准和生成自己的制作文件 |

Overview 与 Resources 可并行进入；Analysis、Series 和 AI 生成都是按需动作。界面给下一步建议，但不做逐页解锁的向导。每次生成说清它使用哪些已确认的输入、哪些未知；没有任何可用依据时说明最少需要给什么。不是把空输入当成依据，也不强迫专业用户填写一张长表才能开始探索。

## 2. 先对齐：页面、对象与用词

| 用户看到的词 | 含义 | 归属 |
| --- | --- | --- |
| Project | 品牌、目标和一组工作所处的本地容器 | 项目首页 / 项目导航 |
| Project brief | 已采用的任务输入，如品牌、产品、受众、目的、平台、时长及可用主张 | Overview |
| Resource / Reference | 已进入本地项目库的文件；Reference 是本次选择用于借鉴的来源，文件位置单独管理 | Resources |
| Source Review / Evidence Timeline | 核对某个原视频在什么时间出现哪些证据 | Resources 的第二种工作视图 |
| Reference analysis | 解释来源的创意意图、结构、手法及可借鉴之处 | Analysis |
| Series | 可选的系列，定义一组新视频共享的主题或形式；没有自己的拍摄包 | Content plan |
| Video | **计划制作的一条新视频**；可独立或属于系列。不是上传的参考视频，也不会立即生成媒体 | Content plan |
| Direction | 这条新视频的一种创意拍法；可有多个备选，但此刻只批准一个确切版本 | Content plan |
| Production pack | 同一条新视频的拍摄交付：精简 Production brief ＋一行一镜的 Storyboard Sheet | Production |

例如：Project「Travel Mug Launch」→ 可选 Series「通勤实测」→ Video「倒置漏水挑战」→ 方向 A「包里倒置实测」/ B「通勤场景对比」→ 批准 A → 进入同名 Video 的 Production 得到文档。只做「倒置漏水挑战」一条时，从 New video 开始即可。

**1.8.2 混淆的原因：** New series 与 New video 并排；页顶同一个输入框同时服务于项目级的系列/选题建议和单视频方向；“Suggest series & topics”把生成条目直接保存进计划。新版需要拆开动作和对象，而不只是把按钮改个颜色。

## 3. 按工作区的功能 PRD

### P0 · 项目首页 / 通用工作区

- 项目首页保持专业软件式网格：New project、搜索、最近使用、打开；重命名、独立复制、移入废纸篓和恢复放项目菜单。不将可恢复删除变成永久清理。已存在的项目、原文件、证据、批准、文档与本地路径保持可读。
- 项目内左侧保持 Overview / Resources / Discover / Analysis / Content plan / Production 的稳定顺序。窄窗可收起导航，仍有可读名字；保留全局回到项目首页。
- 页头表达“当前在做什么”和下一步，主操作随当前任务切换。生成/导入/保存状态不挤占导航。Content plan 与 Production 共享当前计划视频；只浏览别的报告、资源或历史，不得顺便切换当前制作对象。
- 界面状态使用普通语言：本地已保存、处理中、部分可用、需要重试、输入变动需复核。默认只出现一次。Activity / Help 提供失败任务的 Copy diagnostics；保留 1.8.2 的脱敏支持信息，但在日常内容和文件卡上不显示内部 ID、异常码、长日志或模型原文。

**验收：**旧项目打开、刷新、重开、复制、恢复正常；浏览项目级 Analysis 后回 Production 仍是原视频；切换标签不会丢草稿或启动新请求。

### P1 · Overview：和 AI 说明任务，审阅项目理解

- **主区是聊天。** 空态 “What do you want to create today?”，支持直接描述、粘贴和附资料。只有答案会改变目标、方向、受众或重要约束时才主动追问；每轮最多一个问题，默认最多两轮主动澄清，然后出可审阅草稿。已有足够信息时零追问；用户说先继续就给草稿并标缺口；非关键问题留做可选补充，用户可主动深入。正式制作确实缺必要信息时，在触发对应操作时只提示具体缺口，不用聊天一直拦人。不把未知或推断自动采用。
- **同一个位置切换 Send → Stop → Send。** 运行时用清晰方形停止图标和可访问名称 “Stop response”。用户可以停止当前回复并继续用聊天。排队未执行的任务不发出；运行中的请求尽可能取消，阻止后续步骤及迟到的回复/Brief 提案写入。保留原消息、附件、已确认 Brief，气泡只写 “Stopped”。明确 Retry 使用同一条已存消息、区分不同尝试，不重发消息、不自动重试。已发出的请求可能已经产生费用；不能只关前端动画冒充取消。停止只针对当前回复，不一起停素材处理或其它生成任务。
- **保留 Project brief，重做成快照。** 宽窗右侧、窄窗用 “View brief” 打开。首屏最多几组短信息：品牌/产品、受众、主要目标、平台/时长、可用主张与重要限制；仅显示影响下一步的缺口。用 “In use” 区分已采用内容；有草稿时只有一个 “Review changes (n)” 入口。没有已采用内容时明确空态，不显示假“已应用”。
- **审阅视图**只比较发生变化的内容：现值、建议值、消息/文档来源、可选的直接编辑，以及确认使用、保留现值。移除首屏 Restore suggestion、Add a correction directly、Excluded information 大区块和常驻禁用 Apply。历史/撤回建议放深层菜单，简易编辑留在审阅内，主要更正入口仍是聊天。用户审核后一个 “Apply updates”；去掉或采用涉及主张的内容应显式确认，允许使用不等于事实已验证。
- 资料意图优先支持 Word、PDF、Excel 等常见项目输入，但只宣传经实测的格式与解析范围；支持本地保存和能读出可用于 Brief 的内容是两件事。扫描件、复杂表格或不能解析的文件要说清限制并允许贴文字；已上传原件留在 Resources，不重复上传。后台保留安全回复与独立提案校验：一条提案失败不吞掉有效回复。
- 仍保留草稿与正式采用分离、相同内容不产生新版本、真实变更才标记受影响的下游复核。停下的旧尝试不能覆盖新草稿或已采用内容。

**验收：**双目标场景收到一个清楚的问题，无未经确认的信息被应用；拒绝某条提案仍可看到完整安全回复。补充测试信息充足零追问、单一歧义一轮、信息稀少两轮后给可审阅的有限草稿、用户要求先继续不再追问。测试排队时 Stop、请求中 Stop、完成与 Stop 竞态、Stop 后 Retry 旧请求迟到；刷新后状态正确。中文输入法按 Enter 选词不误发送。

### P2 · Resources：先是项目文件系统，再进单文件审看

**现况与改法。** 截图四个标签里，All resources 是聚合视图；References、Documents、Production assets 是用途筛选，1.8.2 没有真实的项目文件夹层级。现有上传规则主要按扩展名猜参考/文档，Production assets 筛选会强制指定用途。黄色长段是多个后端限制拼在一起并被卡片和预览重复显示；该截图的脱敏记录指向语音时间戳校验，不能从它推出 API 欠费。迁移文件缺缩略图是可能情况，截图已能播放，不能把无缩略图等同于无媒体。

- **Media Pool 默认列表。** 左侧目录树，顶部面包屑、Search、Upload files、New folder、List/Grid 开关；中间显示名称、文件类型/格式、导入时间、大小、视频时长。未知显示 —；时长和文件大小不猜测。列表可排序和多选。平铺采用轻量文件/文件夹图标，同一套信息可在紧凑卡片及详情取得；不再常驻缩略图卡或右侧自动播放占位。
- **已确认的预置方案：**保留 All files 聚合视图，加四个实际起始文件夹：Inbox、References、Documents、Production Assets。Inbox 是新增起始文件夹，另外三个沿用既有用途名称。用户可创建子目录、重命名、移动；删除走可恢复操作，受引用文件显示影响。双击目录进入。多选 Move to 提供键盘可用路径，拖放可作为快捷方式。
- **放哪由用户和入口决定。** 当前目录内上传默认进该目录，可在导入时更改；在 All files/根级不指定就进 Inbox。Overview 附件默认 Documents，未来 Discover 接入的本地文件默认 References。系统识别媒体类型、时长、大小和基础状态；不猜文件的商业用途、不擅自搬家、不因归入 References 就自动纳入当前分析。目录、文件类型、来源（用户/Discovery）、用于哪次分析都分开。在后台确实还需要分析用途字段时，做明确映射或动作；不能把目录名称当类型权限。
- **本地原件与引用。** 灵活组织的是项目内逻辑目录；现有项目拥有自己的原件和缓存。移动和重命名不得重新上传、重做识别或让历史时间戳失效；重名可无损保留或请用户选择。删除有引用文件，保留历史引用，并提示不可访问的状态和恢复入口。迁移旧项目按原用途组织、留存证据；不编造导入时间、媒体精度或缺少的轨道。
- **勾选 ≠ 打开预览。** 点击打开的是焦点/预览，多选勾选的是分析范围。底部仅在有选择时显示 “Analyze 3 references”；点开明确本次对比文件、项目探索还是当前计划视频，以及证据缺口。切目录不丢选项；未点分析前不调用付费结构分析。保存选择可自动保留草稿，避免出现含义不清的 “Save selection” 和 “Analyze” 平行按钮。
- 对部分转录，在选中的来源或相关操作旁一次性显示 “Partial transcript · Retry missing speech”。默认只提供相关动作，重试保留已完成的观察与人工校正。完全无语音时，“No speech detected”“Speech unavailable”“Transcript incomplete”分开；仅用现有视觉/屏幕文字继续分析时需明确确认，并将限制保留在报告中。技术日志移到 Activity 的失败记录。

**验收：**同一视频放进 Documents 仍可以按媒体类型预览和在明确选择后分析；移动文件前后的证据引用可打开同一时间点。未选文件或预览坏了也能管理库。部分失败只有一处提示，并能重试缺失语音。

### P3 · Resources / Source Review：恢复 v0.7 时间线体验

**当前可复用资产。** 1.8.2 仍能从 legacy 工作区进入 `ReferenceWorkspace.tsx` 与 `AnalysisReview.tsx`；新版资源侧栏只呈现按时间排序的文字。迁移的是旧版的播放器、时间尺、播放头、证据轨道、事件定位与校正交互。实现时用 1.8 项目库的媒体与证据修订，不能简单嵌入整套旧任务页或假定新旧数据一一对应。

- 双击视频、选 “Open in Timeline”，或从 Analysis 点引用，都打开**同一个** Source Review；可返回原目录或原报告。宽窗布局：左侧可收起的媒体列表，上部播放器和选中证据 Inspector，下部全宽时间线。窄窗改成播放器＋时间线，详情按需展开。普通文件浏览不一直挂着这个布局。
- **查看优先看段落，验证时打开轨道。** 上层显示已有可用证据支持的创意段落，如 Hook、Setup、Proof、CTA，明确这是对角色的解读；没有可靠段落时显示实际已有轨道，不凭空划分。下层共享一个播放头：画面观察、屏幕文字、语音、其他音频（有资料才显示）。画面采样点用点，已知持续区间用块，估计时间或缺口有单独表现；不暗示采样等于逐帧完整分析。
- 播放/暂停、拖动时间尺、缩放、适配全长、跳上一/下一证据，点证据就跳到相应时间；已验证的源/代理时间映射才允许宣称按帧精度。可搜索 Transcript，点击结果回到同一播放头；长文字放搜索面板或当前证据详情，不替代轨道。
- 可校正识别出的文字/画面描述以及允许编辑的段落角色；原视频、真实播放时长和原始识别证据不可修改，不提供切割、拼接、调速、混音。校正有独立版本；草稿不影响下游，应用后才使真正引用该修订的结果需要复核。
- Analysis 的来源跳转带上资源、证据版本和时间范围。历史引用默认打开其使用的版本，可显式切换到当前；文件已移走、旧字段未迁移、时间戳不可用时必须讲清楚，不能跳到另一条近似记录。

**验收：**点视频内任一时间段，播放器与 Inspector 联动；刷新可重新找回本地证据；旧项目没有可迁移角色段时能播放并展示真实轨道；历史分析引用不被最新识别替换。

### P4 · Discover：预留第二条入库渠道

保留与其它 Tab 一致的轻量空态，说明发现功能尚未开放，可返回 Resources 上传本地文件。无假结果、无不可用的下载按钮。未来 Frank 定义的发现流程一旦有合格本地文件，经同一个项目入库入口入池并记来源；用户上传与发现共享目录、缓存、来源定位和选择能力。当前保留边界，不决定平台、抓取方式、授权规则、模型或指标阈值。

### P5 · Analysis：先给可用判断，再看结构图

- **首屏顺序：**①小型标题、分析范围、来源数量、保存/过期状态；② **Key insights**；③单来源 Structure flow 或多来源 Comparison；④按需看原始证据与覆盖。图表上方不再交付同一大段摘要，首屏也不要大号 Key takeaway。若旧报告长摘要有独立上下文，只在历史/详情读一次。
- Key insights 为 **最多 3–5 条**有区分、有用的判断，少于三条也可。每条固定为「观察或策略判断」＋「为何与任务相关/如何借鉴」＋「可定位的来源」。例如「场景让症状具体化 → 用用户熟悉的日常情境建立相关性 → 查看 00:20–00:27」。平台数据、目标与人群无从证实时写“推测”或“未知”；不把视频自述当真实事实，也不说某手法已带来更高转化。
- **营销判断覆盖**：观察或推断传播目标、核心信息、可能受众、Hook、主体/元素/场景的功能、证明或限制、CTA 以及如何应用到当前项目。按证据输出，不强行每栏都填。若需产品/公司背景，可沿用已有有界来源研究，标记出处及不确定项，不得自动写入 Project brief 或为视频推定成效。
- **结构图**分开呈现视频观察、视频中的主张、分析推断；浅色/不透明节点面＋清晰文字、有文字标签和边关系。主链读得懂，次级连接按需看。默认 fit；支持缩放、平移、复位、键盘以及按序列表替代。图只在自身区域平移，不能把整页推出视窗。点节点显示它的功能和少量来源跳转。1.8.2 有旧深色节点背景与新主题文字混用的迹象；实施时逐类检查实际样式，不用简单滤镜盖掉问题。
- **多参考**先展示跨片相同机制、差异、适用条件；逐条独立结构图通过来源切换。报告中项数量、缺失声轨、声明范围清楚；比较不虚构趋势或统计。分析范围切换为浏览状态，不修改当前计划视频。可 “Use insight in Content plan” 把来源链接交给创意草稿，由用户选择采纳。
- **本地保存语义：**每个分析范围只默认展示最新成功结果。新分析成功才替换当前展示；处理中、失败、取消时旧报告仍可读；历史为轻量入口。影响当前结果的来源/已采用输入发生变化时标记 “Inputs changed · review”，不自动付费、不删旧报告。不将部分转录的旧报告悄悄标成全覆盖。

**验收：**第一屏能说出主要洞察，不出现两次同义摘要；每个有证据的洞察可跳到具体来源；图节点在默认、悬停、选中、键盘聚焦下都可读；重开还在，失败不覆盖成功结果。

### P6 · Content plan：决定拍哪条、怎么拍

- 默认主按钮 **Plan a video**，最低只需标题/题目，可无系列。系列放二级入口 **Create series**；系列内有 **Add video**。已建独立视频应可后续归组/移出，保持该视频的 ID 和文件关联。暂不做发布日历、时间排期或批量生成生产包。
- 左侧是已有视频计划和可折叠系列，右侧只展示所选视频：题目、目标/平台、引用范围、当前方向步骤。不做项目级提示框和单视频任务共用输入。
- **选题建议**在计划层，回答「接下来有哪些视频值得做」；用 **Suggest topics** 预览少量候选，用户明确 **Add to plan** 后才建条目。系列建议只在系列场景露出。**方向建议**在指定视频内，回答「同一条视频可以怎么拍」；可 **Write a direction** 或 **Generate directions**，默认给两个真正不同的拍法。每个卡片说创意主张、开头 Hook、基本执行、证据/约束和代价，便于比较。
- 可在已有参考、已采用上下文或用户给出的具体创意指令任一存在时开始探索；缺的信息标 **Needs confirmation**。不能用未采用的事实补足正式制作，生成失败时不留下空系列或重复条目。点卡片是查看，**Approve direction** 才批准该确切修订。修改方向后须重新批准；换方向不会删除旧结果。获批后出现 **Open Production**，直达同一条视频，不让用户再选一次。方向发生改变且受影响的旧制作包保留标记。
 
**验收：**首次只做一条视频，用户不需理解 Series 即可完成；Topic 不等于 Direction；没采用的建议不进入计划；选中方向与批准清楚区分，制作对象在跨页过程中相同。

### P7 · Production：一张可交给拍摄团队的 Storyboard Sheet

- 独立 Production Tab 保持 Content plan 的同一条 Video。顶部显示视频、已批准方向、保存状态及 **Export sheet**。没有 Video 或获批方向时只给一个明确的去处：Plan a video / Review direction。
- **默认主交付是一张 Storyboard Sheet，一行一镜。** Production brief 是表上方的短摘要（目标、受众、平台、时长、执行限制与可使用的主张）。逐镜台词是可用脚本，镜头与备注也是可用 shot list；新版不再把旧四件套并列为主交付。
- 桌面表头顺序：**Shot · Timecode · Framing / Camera · Visual / Action · Dialogue / VO · On-screen Text · Music / SFX · Production Notes**。Timecode 是新片计划时间，不是参考视频证据时间；显示为起止区间。逐镜可选关联参考，不要求自动生成分镜图。导出默认提供干净可进 Excel/Sheets 的 CSV，使用数值 Start/End 分列；元数据、内部 manifest 与来源记录不要混进主表行。保留旧历史版本按原格式读取/导出；原有打印或其它导出不必抢主入口。原生 XLSX 不是本版发布门槛。
- 以版本化的结构化镜头作为新版表格的事实来源，避免表格、脚本和 CSV 各自改出不同版本。编辑、保存、重开、导出都对应同一修订。升级时保留 1.8.2 的已存 brief、脚本、分镜、shot list 和手工编辑；能准确投射的已存结构化镜头才转换。没有可同步镜头的旧版本继续可读、可导出，不猜镜头与时间，也不静默覆写。若正式新增镜头字段，统一 owner 更新正式模型、生成契约与兼容测试。
- 生成前保留 1.8.2 的正式准入：当前确切获批方向、有用的已采用上下文、确实绑定的参考证据已审阅且没有未处理的校正；AI 生成带时序的表需已确认时长。没有参考时不强制新增。露出缺失条件与跳转，保留手工起稿。上游修改只标记受影响版本复核；重新生成不会吞掉人工改稿。不做剪辑、Render 或 Publish。

**验收：**从获批方向开同一条视频；一张表即可读出每个镜头怎么拍、说什么、何时出字；修改一行保存并重开，导出与所见保存版本一致；无法转换的 1.8.2 历史不丢失。

## 4. 跨页布局与浏览器验收

视觉保持浅蓝/淡紫 Glassmorphism。玻璃效果放导航、外框、少量工具条；正文、时间线、图表节点和长表格采用稳定的阅读底色。信息跟着任务分组，避免每句话一个卡片、所有操作一个视觉权重。以现代 Web 指南的布局、弹层、动态状态、键盘焦点和媒体建议制定以下验收；实现阶段按具体问题检索指南，并验证目标浏览器与必要回退。

| 问题 | 规格 / 验收 |
| --- | --- |
| 浏览器缩放后裁切、页面滚不了 | 桌面宽窗可分栏；栏位实际空间不足时让工具条换行、Inspector 改抽屉、长文字重排。每页明确主滚动区。仅时间线和结构图可局部横移；必要的宽表也应只在表格区滚动。固定操作条不遮正文最后一行，焦点始终可滚入视野。 |
| 分栏内的拥挤 | 以容器宽度而非屏幕型号决定重排；用可预测的 Grid/Flex 分栏、合理正文宽度、保留播放器比例。禁止仅用裁切或横向伸长把问题藏起来。 |
| 节点、按钮、文本在浅玻璃上读不清 | 按 WCAG 2.2 AA 检查实测前景/背景：普通文字至少 4.5:1，大文字至少 3:1；控件边界/焦点及图中必要提示另测。含义有文字/形状，不只靠颜色；不可读的节点默认状态不能靠 hover 才能读懂。 |
| 弹层和键盘 | 审阅与确认对话框可用键盘进出，Escape 关闭允许关闭的弹层并归还焦点；重命名、多选、移动、时间定位有键盘替代。播报任务状态时不取走用户输入焦点，不用 CSS 装饰替代标签或状态。 |
| 处理状态和媒体拖慢界面 | Media Pool 不给所有行加载视频；只在用户打开的媒体视图加载需要的播放器。部分完成、失败、取消从相关动作显示一次，不用顶部警告、卡片、播放器同报三次。 |
| 演示与回归矩阵 | Chrome + Safari，1440×900 和 1280×800，100%/125%/150% 缩放；另测窄窗与 200% 文本/页面放大，支持关键正文与控件重排。以长中英文标题、长文件名、键盘、中文 IME、空态、处理中、失败、缺轨、历史版本为场景。图表/时间线必须有可以读到内容的替代入口。 |

参考：[Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance)（本次阅读版本 `64a6d708f5a43f2cd3fde5d4d7db3905ba1bdf65`，关注 responsive-design、size-aware-styling、css-layout、overflow、IME、可访问错误和延迟加载媒体）；[W3C 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；[W3C 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

### 4.1 布局默认值（可随实际容器微调）

- **通用：**桌面导航约 200 px；宽屏工作区 24 px 间距，窄窗优先收侧栏与次要按钮。业务正文有自己的清晰滚动区域；不要为“对齐”隐藏可达内容。照片和标志样式只是示例，统一沿用产品现有标识。
- **Overview：**正文双栏约 **2:1**，Brief 建议 **300–360 px**；聊天输入在聊天区域底部，正文滚动不遮最后一条。内容区不足约 900 px 时改成单栏＋View brief 抽屉。
- **Resources：**文件夹树 **180–200 px**，表格占剩余宽度。空间不足收起目录树，列表控件允许换行，保留可达的 Move to / Open in timeline。
- **Source Review：**面板上部播放器/选中证据约 **2:1**，视频保持原比例；下部全宽时间线，常态约工作区可用高度 **30–35%**、至少约 **220 px**。低高度可滚动到完整轨道，不挤没工具条；窄窗把证据面板换成抽屉或播放器下的折叠区。
- **Content plan：**视频/系列清单约 **240 px**，剩余空间给当前 Video 的方向；窄窗改为可收起清单。Analysis 首屏优先 3 条短洞察，图表跟在其后。
- **Production：**八列宽度初始权重为 **6 / 11 / 11 / 20 / 18 / 12 / 9 / 13%**；时间码和镜号稳定，画面与台词优先，标题和正文可换行。表格可在自己的区域横移（建议 1000 px 左右最小布局），窄窗有逐镜阅读入口，整页不横溢。

## 5. 1.8.3 决策与交接

**已确认：**默认单条 Video，Series 可选并保留独立 Production Tab；第四个实际素材文件夹为 Inbox；Source Review 作为 Resources 内独立工作视图。Overview 减少追问；本版采用默认最多两次主动追问再给草稿的规则。Storyboard Sheet 作为当期执行规格的主交付。比例使用 §4.1 的产品默认值，按浏览器可读/可达验收，不寻找像素级一致。此文档批准的是产品范围；实现、PR、发布各自记录。

**UI 参考：**配套八张 16:10 桌面预览位于交接包 `ui/`，以 `START_HERE.md` 中的索引为准。示例使用 Travel Mug Launch；原片 `commute-demo.mp4` 24 秒，新片 The Bag Test 20 秒。图片的精确尺寸、文字、时间戳示例和状态不覆盖本文规则。概念图里的资源高亮≠分析勾选，Overview 的 Brief 草稿≠已采用。

**推荐拆分：**一个 COMM_586 Cloud 总控作为唯一集成 owner；先核对基线并冻住所需共享契约与页面壳。实施拆为 A Overview、B Resources → Source Review → Analysis、C Content plan → Production 三条工作流。B 内顺序推进；C 的基础工作可在共享契约稳定后开始，最终证据联调在 B 后。项目首页、Discover 空态和最终版本/打包由总控负责。模块可在不碰同一契约文件时并行；分对话不是要求每 Tab 一份 PR。推荐从共享基线建立小任务分支，再统一汇报，由总控集成。分工、任务卡与验收见 `MODULE_TASKS.md`。
