## Changes

- Scrolling and wrapping for short or zoomed windows, including expanded resource
  coverage, transcript actions and keyboard focus.
- A concise current Analysis view with individual source structures, separate
  comparisons, expandable evidence and source navigation.
- Saved analysis remains scoped to its project or content item. Valid successful
  replacements become current; failed replacements retain the prior result.
- Context-based ideas can start with an empty creative instruction. Reference-led
  exploration identifies missing context, and visual-only continuation is explicit.
- Missing-speech retries retain successful source observations and corrections.
  Coverage messages distinguish unavailable audio, silence and failed processing.
- Application version and source provenance are visible for bug reports.

Discovery remains **Reserved — awaiting Frank’s specification.** No editing,
rendering, video generation, publishing or hosted credential service is added.

## Open existing projects safely

1. Finish running work and stop the previous application/server before upgrading.
2. Back up the entire library with the application closed. On macOS it is
   `~/Library/Application Support/Video Anatomy/`. Preserve this folder, including
   project databases, source media, evidence, output history and legacy records.
3. Extract the candidate ZIP completely and open its launcher. The Finder app
   uses that same stable library outside the installation folder. Do not move
   project databases individually or delete the library to fix a startup problem.
4. Open an existing project from its card. Saved results do not need another paid
   request. Inspect the selected analysis scope and use Resources for source media.
5. Keep the old app package and backup until the candidate has been checked.
   A legacy task import is independent of subsequent edits in the old workspace.
   For rollback, use a separate copy of the pre-upgrade backup: older binaries
   may reject the additive 1.8.1 fields in an upgraded project record.

If an earlier Terminal launch used a custom `--data-dir` or
`VIDEO_ANATOMY_DATA_DIR`, Finder intentionally opens the standard library instead.
This can make work appear absent without deleting it. Stop the Finder server and
run the extracted local bundle with `bash scripts/start-local.sh --data-dir "/absolute/path/to/your/existing/library"`. Keep that path unchanged;
do not merge SQLite files manually or overwrite the standard library. The local
runtime diagnostics report the active library path.

The Mac ZIP is an unsigned, dependency-assisted Finder launcher, not a standalone
DMG. It requires Python 3.12 and FFmpeg/ffprobe; first launch installs pinned
Python dependencies with internet access. Optional scanned-document OCR requires
Tesseract/Poppler. Node is not needed to run the prebuilt UI. macOS signing,
Gatekeeper, Keychain and native installation require real Mac testing.

## Team testing checklist

- Record About version/commit, OS/browser, viewport and browser zoom.
- Open an existing project and create a fresh one. Confirm conversation and brief
  review work without repeating onboarding.
- Expand long transcripts and coverage panels. Reach lower actions using both
  pointer and keyboard at 100%, 125% and 150% zoom.
- Open the current analysis, follow graph/evidence links to the correct video
  moment, navigate away, refresh, close/reopen the tab and restart the app.
- Generate a replacement analysis; confirm a failed replacement leaves the last
  successful result visible, including when using different content items.
- Try ideas with context and an empty instruction, then reference-only exploration.
  With neither source, expect a useful starting question. Review visual-only
  limitations before explicitly continuing when speech is unavailable.
- Retry missing speech on a corrected reference. Confirm visual observations and
  corrections remain intact. Record the displayed diagnosis without sharing keys.
- Edit and save a storyboard/production pack; reopen it and check the exported
  documents against the saved revision.

Record bugs in the existing team Google Sheet. Include **Version/commit,
OS/browser, viewport/zoom, project/reference, reproduction steps, expected
result, actual result, screenshot/recording, severity, and retest result**.
Frank will review reports and assign follow-up work. No new tracking system or
teammate assignment is introduced by this release.
