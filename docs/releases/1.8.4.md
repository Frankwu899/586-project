# Video Anatomy 1.8.4 — reliability and plan management candidate

This local testing candidate follows the merged 1.8.3 source at
`d4f939f8904b345a05e7a05d818a72860a1b9bbe`. Keep a closed-library backup before
opening saved work with the newer application.

## Reference evidence and final analysis

Reference recognition saves individual source evidence. The later synthesis
request creates a separate cross-reference report. A saved timeline therefore
does not establish that report synthesis succeeded, and partial speech is not
the same failure as a missing report citation.

The report validator now resolves every supplied source/event against the exact
selected evidence revision and builds its source index from validated report,
insight and graph citations. An omitted redundant top-level index no longer
discards otherwise valid, source-linked structures. Invalid or fabricated
citations, unsupported graph relations and changed inputs still reject the
replacement without overwriting a saved report.

Retry report synthesis reuses the task's frozen source scope and saved evidence;
it does not restart recognition. If the reference selection has since changed,
start a new analysis from Resources rather than silently restoring an old scope.
For older tasks that did not retain their request scope, explicitly select the
references in Resources, then choose **Use saved evidence only** in the analysis
confirmation. This creates a report from the displayed selection without
repeating recognition or discarding the available partial transcript.
Activity distinguishes the parent report from named source tasks, records actual
phases and exposes processing details even when partial evidence has no error
string. Older tasks without parent/scope metadata remain separate history.

## Speech recovery and model choice

- Recovered machine transcription can replace unedited machine segments in a
  new evidence revision. Previous revisions and unrecovered source coverage stay
  available. Explicitly corrected events remain protected; legacy corrections
  without per-event markers are handled conservatively.
- Whisper remains the compatibility default and supplies estimated segment
  timestamps. Its strict bounds and validation are retained.
- GPT Transcribe is an explicit alternative. Its text belongs to the measured
  input audio chunk, so new evidence is marked as a whole-chunk interval. The
  application does not manufacture sentence or word timestamps. Retained human
  events keep their original precision when a new attempt conflicts with them.
- Changing a selector makes no inference request. Start recognition explicitly.
  Retry without a model override reuses the source's saved profile; there is no
  automatic paid fallback to another model. Provider caches separate profiles.
- Source Review separates saved-revision diagnostics from the latest failed
  attempt and keeps the actual requested profile visible on failures.

Current official documentation recommends GPT Transcribe for file text and does
not document the segment/word contract used by Whisper. The older Whisper/4o
transcription family has a published 26 February 2027 retirement date. Availability,
account access and actual recognition quality require live acceptance.

Sources: [file transcription](https://developers.openai.com/api/docs/guides/speech-to-text),
[transcription selection](https://developers.openai.com/api/docs/guides/transcription),
[deprecations](https://developers.openai.com/api/docs/deprecations#2026-08-26-transcription-models).

## Video and Series management

Content plan has explicit creation, search, rename, move, Trash and restore
actions. Videos remain standalone by default. Renaming is organizational and
preserves the original creative-context snapshot, directions, approval and saved
production. Editing creative descriptions or Series concepts still invokes the
existing review gates.

Trashing a Video retains all its directions, sheets and exports. Trashing a
Series keeps its active Videos as standalone items. Restore regroups only items
whose assignment has not subsequently changed; it does not undo a newer move or
steal the currently selected Video. A restored last Video remains unselected
until chosen. Running generation blocks destructive lifecycle changes.

## File intake and compatibility

The default per-file import limit is now **500 MiB**. Existing explicit
`VIDEO_MAX_BYTES` settings continue to take precedence. Resources displays the
server's actual limits and a result for each imported file. Duration remains
180 seconds and each video dimension remains at most 1920 by default; raising
the byte limit does not add unrestricted long-video, HDR or 4K support.

Projects, original media, human corrections, adopted Briefs, saved analyses,
approvals and exports remain in the existing local library. Storage schema family
stays 1.8.0 with additive defaults. Old application binaries may reject newly
saved fields: use a separate pre-upgrade backup for rollback and keep the newer
library intact. Keychain behavior, Sol for text/vision, client usage accounting
and the historical experiment ledger are unchanged.

## Mac acceptance

The single Mac test ZIP contains only `README.txt` and `Video Anatomy.app` at its
root. It is an unsigned dependency-assisted Finder launcher requiring Python
3.12 and FFmpeg/ffprobe; first launch installs pinned Python dependencies.

1. Close the old application and back up the complete library. Confirm version,
   source commit, the expected old projects and Keychain connection after launch.
2. Inspect the reported partial files, including failure code and requested
   model. Test one explicit speech retry; compare real wording and source timing.
3. Try the optional GPT model and verify its coarse audio-chunk labeling. Do not
   interpret it as a sentence-aligned transcript or assume account permission.
4. Retry report synthesis and follow its saved citations. Rename, move, trash and
   restore a planned Video/Series; reopen the same production and export a sheet.
5. Check keyboard operation, narrow windows and browser zoom.

No scraping, media editing, rendering, generated video, publication or hosted-key
service is introduced. Final measured verification is recorded in the
[1.8.4 handoff](../handoff/project-workspace-1.8.4.md). Offline authored fixtures
do not establish the root cause of the owner's original files or live model
quality. Actual macOS, Safari, account permissions and inference remain separate
acceptance checks when they cannot be exercised in Cloud.
